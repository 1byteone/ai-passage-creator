## 1. 项目目标与页面角色

### Q1. 本轮优化的主对象是什么？

- A（推荐）已有产品页面体系优化
  - 优点：风险更低，能直接服务现有业务和代码
  - 缺点：会受到历史结构和视觉包袱限制
- B 新页面从零搭建
  - 优点：能一次性建立更完整的系统
  - 缺点：成本更高，验证更慢
- C 局部功能页修补
  - 优点：见效快
  - 缺点：难以解决系统性问题

### Q2. 你更希望这轮优化覆盖哪些页面？

- A（推荐）首页 + 工作流页 + 结果页 + 后台页
  - 优点：能建立全站一致性
  - 缺点：范围大，节奏要控制
- B 只做面向用户的前台页
  - 优点：更容易形成品牌体验
  - 缺点：后台割裂感会保留
- C 只做高频工作流页
  - 优点：能优先改善真实使用体验
  - 缺点：首屏获客与品牌表达改善有限

### Q3. 这轮优化最重要的结果是什么？

- A（推荐）提升任务完成率和转化
  - 优点：最容易衡量业务收益
  - 缺点：视觉突破可能更克制
- B 提升品牌感和高级感
  - 优点：感知提升明显
  - 缺点：如果缺少真实证据，容易变空
- C 提升开发维护效率
  - 优点：长期收益高
  - 缺点：短期用户感知未必最强

### Q4. 核心用户更接近哪一类？

- A（推荐）首次进入的新用户
  - 优点：有助于优化首屏与理解速度
  - 缺点：高阶效率功能会被后置
- B 已登录的回访用户
  - 优点：更适合优化效率与复用路径
  - 缺点：陌生用户理解成本可能保留
- C 内部运营或管理员
  - 优点：决策链短，更强调实用
  - 缺点：品牌表达的重要性会下降

### Q5. 页面最应该帮助用户完成什么？

- A（推荐）快速理解并开始操作
  - 优点：最适合产品化首页和工作流入口
  - 缺点：深度说明空间有限
- B 深度比较后再决策
  - 优点：适合高单价或复杂产品
  - 缺点：页面会更长更重
- C 高频任务快速执行
  - 优点：效率很高
  - 缺点：对陌生用户不友好

### Q6. 页面角色更偏向哪种？

- A（推荐）混合型：获客 + 激活 + 工作流
  - 优点：符合当前仓库现状
  - 缺点：需要更细致的层级设计
- B 纯营销型
  - 优点：叙事与品牌表达更集中
  - 缺点：不适合复杂业务流程
- C 纯工具型
  - 优点：更专注效率
  - 缺点：首屏吸引力可能不足

### Q7. 优化完成后你最想先看哪个指标？

- A（推荐）主操作点击/提交率
  - 优点：最接近业务价值
  - 缺点：需要埋点清晰
- B 用户停留和滚动深度
  - 优点：容易观察内容吸引力
  - 缺点：不能直接证明成功
- C 页面满意度反馈
  - 优点：直观
  - 缺点：主观性更强

### Q8. 当前最痛的页面问题是什么？

- A（推荐）信息层级和页面结构
  - 优点：解决后收益最大
  - 缺点：需要动到更多模块
- B 视觉陈旧或模板感重
  - 优点：短期体感提升快
  - 缺点：若不动结构容易只是换皮
- C 性能或响应式差
  - 优点：能直接提升可用性
  - 缺点：视觉和品牌问题会保留

## 2. 首屏与信息架构

### Q9. 首屏最重要的职责是什么？

- A（推荐）说清产品是什么并给出下一步
  - 优点：降低认知门槛
  - 缺点：个性表达会更克制
- B 用强视觉先抓住注意力
  - 优点：记忆点更强
  - 缺点：可能牺牲清晰度
- C 直接让用户进入操作
  - 优点：效率高
  - 缺点：不适合完全陌生用户

### Q10. 你更接受哪种首屏叙事方式？

- A（推荐）产品名 + 价值说明 + CTA + 真实界面暗示
  - 优点：专业且可信
  - 缺点：需要真实素材支撑
- B 口号式 Hero
  - 优点：更容易写
  - 缺点：容易空泛
- C 纯输入即开始
  - 优点：极简直接
  - 缺点：说服力和品牌感偏弱

### Q11. 页面整体风格应该偏哪种？

- A（推荐）Precision System
  - 优点：适合当前工具与业务页面混合场景
  - 缺点：情绪张力相对克制
- B Editorial Restraint
  - 优点：更有高级感和差异化
  - 缺点：对内容与素材要求更高
- C Immersive Digital
  - 优点：视觉冲击强
  - 缺点：实现、性能和维护成本高

### Q12. 页面模块应按什么逻辑排序？

- A（推荐）按用户任务流排序
  - 优点：最符合使用场景
  - 缺点：需要更深业务理解
- B 按功能清单排序
  - 优点：实现快
  - 缺点：容易模板化
- C 按品牌故事排序
  - 优点：情绪连贯
  - 缺点：任务导向可能变弱

### Q13. 是否需要明显的“证据区”？

- A（推荐）必须有
  - 优点：更能建立信任和说服力
  - 缺点：需要准备真实材料
- B 轻量化呈现
  - 优点：更克制
  - 缺点：转化说服力较弱
- C 暂时不突出
  - 优点：页面更轻
  - 缺点：容易显得只是会说

### Q14. 证据更适合用什么表达？

- A（推荐）真实界面、流程样例、结果样例
  - 优点：最贴近产品事实
  - 缺点：素材准备成本高
- B 数据指标或案例
  - 优点：有说服力
  - 缺点：需要真实数据
- C 用户评价
  - 优点：社会证明强
  - 缺点：如果不真实会很伤信任

### Q15. 首页模块数量更适合哪种节奏？

- A（推荐）中等模块数，强调每块有明确任务
  - 优点：信息和节奏平衡
  - 缺点：需要更细排版
- B 短页，快速结束
  - 优点：干脆
  - 缺点：说服与解释可能不足
- C 长页，完整讲故事
  - 优点：适合复杂产品
  - 缺点：疲劳感更强

### Q16. 导航更偏哪种策略？

- A（推荐）精简导航，突出主入口
  - 优点：决策更聚焦
  - 缺点：深层信息会藏得更深
- B 完整导航
  - 优点：覆盖全面
  - 缺点：首屏干扰更大
- C 弱导航，靠页面内部推进
  - 优点：更沉浸
  - 缺点：可探索性差

### Q17. 是否要把“回访用户入口”放到首页更前面？

- A（推荐）要，但不能压过主 CTA
  - 优点：兼顾新老用户
  - 缺点：需要控制视觉层级
- B 不要，首页只服务新用户
  - 优点：路径更纯粹
  - 缺点：回访效率会差
- C 要，且很突出
  - 优点：对老用户友好
  - 缺点：会分散获客页面焦点

## 3. 视觉与品牌系统

### Q18. 是否保留现有绿色主品牌方向？

- A（推荐）保留，但重构角色层级
  - 优点：连续性强，改造成本低
  - 缺点：创新空间稍受限
- B 部分保留
  - 优点：能更灵活地焕新
  - 缺点：需要重新梳理品牌感知
- C 完全改色
  - 优点：焕新最强
  - 缺点：风险最高

### Q19. 整体调性更偏哪种？

- A（推荐）专业可信
  - 优点：最适合工具和工作流产品
  - 缺点：戏剧性较弱
- B 年轻先锋
  - 优点：记忆点强
  - 缺点：容易过时
- C 亲和温暖
  - 优点：友好
  - 缺点：决断感可能不足

### Q20. 视觉密度更适合哪种？

- A（推荐）中密度
  - 优点：最平衡
  - 缺点：设计需要更细腻
- B 高密度
  - 优点：效率高
  - 缺点：容易压迫
- C 低密度
  - 优点：呼吸感强
  - 缺点：信息承载会下降

### Q21. 是否继续大量使用卡片作为主结构？

- A（推荐）仅在真正需要边界的地方使用
  - 优点：更高级、更像系统设计
  - 缺点：布局难度更高
- B 大量卡片化
  - 优点：模块清晰，开发安全
  - 缺点：模板感最重
- C 基本取消卡片
  - 优点：更克制
  - 缺点：边界感可能不足

### Q22. 字体策略更适合哪种？

- A（推荐）无衬线为主，控制字重
  - 优点：清晰、稳定、实现成本低
  - 缺点：个性表达稍弱
- B 标题更有风格，正文保持中性
  - 优点：更有品牌张力
  - 缺点：需要更细审美把控
- C 多字体混用
  - 优点：变化丰富
  - 缺点：最容易失控

### Q23. 主 CTA 数量应该如何控制？

- A（推荐）1 个主 CTA + 1 个次 CTA
  - 优点：最平衡
  - 缺点：部分分流需求需后置
- B 只有 1 个主 CTA
  - 优点：最聚焦
  - 缺点：用户分流不友好
- C 多个并列 CTA
  - 优点：覆盖更广
  - 缺点：会分散注意力

### Q24. 图标与视觉素材更适合哪种管理方式？

- A（推荐）统一图标库 + 真实界面/真实素材优先
  - 优点：最稳定、最专业
  - 缺点：灵活度略低
- B 图标统一，素材风格混合
  - 优点：制作快
  - 缺点：整体感容易断裂
- C 自由混用
  - 优点：最省事
  - 缺点：一致性最差

### Q25. 是否需要深色模式？

- A（推荐）需要，但作为第二阶段
  - 优点：更完整，也能覆盖更多场景
  - 缺点：设计与测试成本会上升
- B 首期就必须支持
  - 优点：一步到位
  - 缺点：会拉长当前周期
- C 暂不考虑
  - 优点：聚焦轻量
  - 缺点：后续补成本可能更高

## 4. 工作流与交互体验

### Q26. 你更想优先优化哪类交互？

- A（推荐）核心工作流交互
  - 优点：最接近真实使用价值
  - 缺点：视觉焕新体感可能没那么立即
- B 首页浏览与转化交互
  - 优点：更容易被感知
  - 缺点：深度使用体验未必同步提升
- C 后台与数据交互
  - 优点：提升运营效率
  - 缺点：前台体验变化有限

### Q27. 创作页更适合什么结构方向？

- A（推荐）主工作区 + 可折叠辅助区
  - 优点：桌面和移动都更容易兼容
  - 缺点：实现要更细
- B 继续固定三栏
  - 优点：桌面信息完整
  - 缺点：移动端很难优雅适配
- C 彻底改成单栏
  - 优点：移动端天然友好
  - 缺点：桌面效率可能下降

### Q28. 移动端的辅助信息应该如何保留？

- A（推荐）用抽屉、折叠区、分段面板保留
  - 优点：不会丢功能
  - 缺点：交互设计更复杂
- B 直接隐藏低优先级内容
  - 优点：实现最快
  - 缺点：体验断层明显
- C 完整平铺到主流程中
  - 优点：信息不丢
  - 缺点：主流程会变长变吵

### Q29. 表单复杂度更适合哪种？

- A（推荐）短表单或分段表单
  - 优点：完成率更高
  - 缺点：组织要更讲究
- B 中等复杂度，一屏完成
  - 优点：兼顾信息和效率
  - 缺点：移动端压力稍大
- C 长表单一次性展开
  - 优点：信息齐全
  - 缺点：放弃率高

### Q30. 表单校验更适合哪种？

- A（推荐）失焦校验 + 提交前兜底
  - 优点：最平衡
  - 缺点：实现比最简单方案更细
- B 即时校验
  - 优点：反馈快
  - 缺点：容易造成压力
- C 提交后统一校验
  - 优点：实现简单
  - 缺点：挫败感更强

### Q31. 错误提示更适合哪种方式？

- A（推荐）字段旁提示 + 顶部汇总
  - 优点：恢复路径最清楚
  - 缺点：实现稍复杂
- B 只做字段旁提示
  - 优点：直观
  - 缺点：长表单易漏看
- C 只做 toast
  - 优点：省空间
  - 缺点：最不利于修复

### Q32. 工作流中的日志和提示更适合什么语气？

- A（推荐）专业、直接、低情绪
  - 优点：更适合工具体验
  - 缺点：少一点趣味
- B 轻松活泼
  - 优点：更有人味
  - 缺点：容易和整体专业感冲突
- C 强技术感
  - 优点：高级用户可能喜欢
  - 缺点：普通用户理解成本高

### Q33. 是否需要给工作流做“恢复能力”设计？

- A（推荐）需要
  - 优点：对长流程非常关键
  - 缺点：状态管理更复杂
- B 只做最简单的刷新后回到首页
  - 优点：实现快
  - 缺点：挫败感明显
- C 以后再做
  - 优点：先聚焦主流程
  - 缺点：会留下明显体验债务

### Q34. 空状态最适合怎么设计？

- A（推荐）说明当前无内容 + 给出下一步动作
  - 优点：真正可用
  - 缺点：需要更细文案
- B 只写“暂无数据”
  - 优点：简单
  - 缺点：引导弱
- C 尽量不出现空状态
  - 优点：表面更满
  - 缺点：不现实

### Q35. 加载状态更偏哪种？

- A（推荐）骨架屏 + 阶段化提示
  - 优点：感知更快
  - 缺点：实现要多花一点工
- B Spinner 为主
  - 优点：简单
  - 缺点：等待感重
- C 静默加载
  - 优点：最省
  - 缺点：最容易让用户困惑

### Q36. 动效预算应该如何控制？

- A（推荐）克制型微动效 + 个别关键转场
  - 优点：收益稳定、风险低
  - 缺点：戏剧性不会特别强
- B 多数区域都有动效
  - 优点：体感更活
  - 缺点：容易干扰、影响性能
- C 几乎无动效
  - 优点：最稳
  - 缺点：状态反馈可能偏生硬

### Q37. 是否要统一按钮、状态、进度等微交互？

- A（推荐）必须统一
  - 优点：专业感和系统感最强
  - 缺点：前期需要梳理规范
- B 只统一主流程页面
  - 优点：工作量较小
  - 缺点：全站一致性一般
- C 先不统一
  - 优点：快
  - 缺点：后面更难收口

## 5. 响应式与多设备

### Q38. 设备优先级更接近哪种？

- A（推荐）手机优先，其次桌面
  - 优点：符合多数面向大众产品场景
  - 缺点：如果实际是 B 端桌面主导，会偏离
- B 桌面优先，其次手机
  - 优点：适合运营后台和复杂工具
  - 缺点：手机体验容易变补丁
- C 三端同权
  - 优点：全面
  - 缺点：成本更高

### Q39. 响应式策略更适合哪种？

- A（推荐）移动优先设计，桌面增强
  - 优点：结构更扎实
  - 缺点：大屏编排要额外打磨
- B 桌面优先，移动适配
  - 优点：大屏更容易出效果
  - 缺点：移动端容易牺牲
- C 完全流式自适应
  - 优点：灵活
  - 缺点：实现与测试难度高

### Q40. 创作页在窄屏下该怎么处理？

- A（推荐）核心内容保留，侧栏能力折叠搬运
  - 优点：不中断流程
  - 缺点：需要更细致交互设计
- B 继续像现在这样隐藏侧栏
  - 优点：最快
  - 缺点：功能信息缺失明显
- C 单独做移动版工作流
  - 优点：体验最好
  - 缺点：成本最高

### Q41. 后台图表页在手机上更适合哪种处理？

- A（推荐）单列重排 + 文本摘要优先
  - 优点：信息更可读
  - 缺点：需要重构布局和说明
- B 直接压缩图表尺寸
  - 优点：实现快
  - 缺点：可读性差
- C 移动端只看数据卡，不看图
  - 优点：极简
  - 缺点：损失趋势信息

### Q42. 是否需要考虑横屏与大屏场景？

- A（推荐）需要基本覆盖
  - 优点：更稳妥
  - 缺点：测试更多
- B 只考虑竖屏手机和普通桌面
  - 优点：聚焦
