## 1. 方案摘要

这是一份基于你已确认的 12 个关键问题收敛出来的正式方案。核心结论是：

1. 本轮是对现有产品页面体系做系统优化
2. 第一目标是提升任务完成率与转化
3. 核心用户更偏向已登录的回访用户，而不是纯首访用户
4. 当前最优先解决的问题是信息层级和页面结构
5. 首屏仍然必须说清楚产品是什么，并给出下一步动作
6. 设计方向采用 `Precision System`
7. 保留现有绿色品牌方向，但重构颜色角色
8. 页面 CTA 采用 `1 个主 CTA + 1 个次 CTA`
9. 表单复杂度采用“中等复杂度，一屏完成”
10. 动效采用克制型微动效
11. 响应式采用移动优先、桌面增强
12. 性能优先抓首屏加载与布局稳定性

这意味着本次优化不是一套偏营销的焕新方案，而是一套以回访效率为核心、兼顾新用户理解的产品化重构方案。

## 2. 已确认决策如何改变方案

相比默认版，这 12 个答案带来 4 个关键变化：

### 2.1 用户重心从“首访优先”改为“回访优先”

你选择了 `4B`，这会直接改变首页与高频路径设计：

1. 首页不能只做品牌介绍和首发启动
2. 已登录用户的“继续任务、查看最近创作、快速进入 Skill”要更前置
3. 新用户理解仍然重要，但不能压过回访效率

### 2.2 表单不走“极短表单”，而走“中等复杂度一屏完成”

你选择了 `29B`，这意味着：

1. 不强行把所有表单拆成多步
2. 更强调字段分组、默认值、帮助信息和错误恢复
3. 在创作页和 Skill 输入页里，信息完整性要高于极致简化

### 2.3 目标以任务完成率为中心，不做纯视觉焕新

你选择了 `3A` 和 `8A`，说明这轮更像一次结构优化工程：

1. 首页、创作页、Skill 页首先解决结构问题
2. 视觉升级是服务结构，而不是单独冲锋
3. 所有页面都要围绕“更快理解、更快进入、更少迷失”重构

### 2.4 保持现有品牌色资产，不进行激进改色

你选择了 `18A`，所以：

1. 绿色仍是品牌识别核心
2. 重点不是换色，而是补足中性色层、功能色和表面层级
3. 最终要从“绿色主题”升级为“绿色作为强调色的系统”

## 3. 正式产品与设计假设

### 3.1 产品假设

1. 用户已经知道这是一个 AI 内容创作产品
2. 回访用户更关心“如何更快继续当前任务”
3. 首访用户仍需在首屏快速理解产品定位
4. 工作流页是体验质量的核心战场

### 3.2 设计假设

1. 高级感来自结构、层级、稳定性和节奏
2. 不靠大面积装饰卡片或泛 Hero 堆砌来建立专业感
3. 页面应优先展示任务、结果、证据和状态
4. 微动效只服务反馈和连续性

### 3.3 工程假设

1. 继续使用当前 Vue 3 + Ant Design Vue 体系
2. 使用渐进式重构方式
3. 本轮先做轻量 design token 和模板，不做大规模换栈

## 5. 首页正式方案

## 5.1 首页角色重定义

首页不再只是获客页，而是：

1. 首访用户的理解入口
2. 回访用户的任务分发台
3. Skill 与创作流程的统一起点

### 5.2 首页首屏结构

推荐正式结构：

1. 左侧：产品名、价值说明、主 CTA
2. 右侧：真实工作流界面暗示或结果预览
3. 首屏下方立即可见：回访用户快捷入口或最近任务带

### 5.3 CTA 策略

你选了 `23A`，所以首页 CTA 正式定为：

1. 主 CTA：继续创作 / 开始创作
2. 次 CTA：查看工具 / 最近任务

不建议并列多个同权重入口。

### 5.4 首页重点改造项

1. 强化已登录状态下的快捷继续能力
2. 保留对新用户的产品解释，但压缩泛叙事比重
3. 用真实界面或结果样例替代部分抽象能力卡片
4. 把“最近创作”从后置内容升级为更高优先级模块
5. 减少模板化“功能卖点卡”的占比

### 5.5 首页验收标准

1. 已登录用户进入后 3 秒内能找到继续任务路径
2. 首访用户 5 秒内能理解产品与下一步
3. 首屏只有 1 主 1 次 CTA，没有并列竞争

## 6. 创作页正式方案

## 6.1 创作页角色

创作页是本轮第一优先级页面，因为它最直接承载任务完成率。

### 6.2 结构方向

保持信息完整，但重排结构。推荐正式结构：

1. 主工作区：输入、阶段内容、确认与结果
2. 辅助信息区：流程、日志、提示，桌面可见，移动折叠
3. 状态区：配额、恢复、失败与进度反馈

### 6.3 表单策略

你选了 `29B`，所以创作页不走极简表单，而采用：

1. 中等复杂度
2. 一屏完成
3. 字段分组清晰
4. 默认值明确
5. 帮助说明靠近字段

### 6.4 正式实施项

1. 输入区按“选题 / 风格 / 配图方式 / 配额提示”做明确分组
2. 左右辅助内容改造成可折叠和可替代容器
3. 移除 emoji 和情绪化日志
4. 把当前阶段、下一步、等待原因写清楚
5. 为流式内容、大纲和配图预留稳定空间，减少布局跳动
6. 增强“刷新后恢复”“失败后重试”“中断后继续”的体验语义

### 6.5 创作页移动端策略

你选了 `39A`，因此移动端不是缩水版，而是移动优先重排：

1. 主工作区全宽
2. 流程与日志进入抽屉或折叠面板
3. 重要反馈始终贴近主内容
4. 不允许关键上下文直接消失

### 6.6 创作页验收标准

1. 375 宽度下创作路径完整
2. 任何阶段用户都知道自己在哪一步
3. 表单一屏完成但不显拥挤
4. 页面状态转换清楚，不靠猜

## 7. Skill 页面正式方案

### 7.1 Skill 中心

Skill 中心定位为任务目录，不是卡片展示墙。

实施重点：

1. 每张卡片强调“输入什么、得到什么”
2. 分类和排序优先服务高频回访场景
3. 已用过或常用 Skill 可以更前置

### 7.2 Skill 执行页

因为你更看重任务完成率，Skill 执行页正式目标是：

1. 尽量减少理解成本
2. 用结构化布局降低等待焦虑
3. 一屏表单完成输入
4. 结果承接自然，不跳戏

实施重点：

1. 输入区和进度区清晰分离
2. 一屏输入完成，但字段分组明确
3. 进度区使用低噪声的结构化状态反馈
4. 结果组件支持回看、复制和后续操作

---

## 8. 结果页与详情页正式方案

由于你的目标是任务完成率，结果页不能只是“展示结束”，而应承担继续动作。

正式要求：

1. 结果优先于装饰
2. 复制、导出、继续处理、再调用 Skill 都要路径清晰
3. 长内容阅读结构稳定
4. 图片、章节、摘要、操作区要有清晰层级

---

## 9. 统计页正式方案

你没把后台放到最前，但它仍是全站统一的一部分。

实施重点：

1. 让关键指标和趋势关系更清楚
2. 图表先讲清“意义”，再讲“形状”
3. 手机上优先保留摘要和关键卡片
4. 图表加载失败、无数据、低数据量时都要有正常反馈

### 10.1 色彩

3. 强化表面层、边框层、文本层级
4. 避免整站看起来只是在不同深浅的绿色里变化

### 10.2 组件状态

必须统一：

1. hover
2. focus-visible
3. pressed
4. disabled
5. loading
6. empty
7. error
8. success

### 10.3 动效

因为你选择 `36A`，正式动效策略为：

1. 只做微动效
2. 重点用于按钮、状态切换、抽屉和结果揭示
3. 不使用大范围滚动特效或炫技型转场
4. 统一时长与节奏
