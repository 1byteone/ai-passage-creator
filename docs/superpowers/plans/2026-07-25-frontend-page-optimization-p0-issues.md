这份文档只覆盖 `P0` 任务，也就是当前最值得立即开工的部分。

建议建单顺序：

1. 先建审计和 IA 类 issue
2. 再建 token 与基础组件类 issue
3. 然后建创作页和首页的页面改造 issue
4. 最后建可访问性、性能和动效收口 issue

建议标签：

- `frontend`
- `design-system`
- `ux`
- `responsive`
- `a11y`
- `performance`
- `p0`

## 4. P0 Issues 详细内容

## FP-P0-01 建立前端页面审计与截图基线

### 背景

当前已经有正式方案，但还缺一份统一的页面问题基线，后续很容易在“感觉更好了”和“真的解决问题了”之间打架。

### 目标

建立首页、创作页、Skill 执行页、统计页的截图、问题标注和优先级矩阵。

### 范围

1. `HomePage.vue`
2. `ArticleCreatePage.vue`
3. `SkillExecutePage.vue`
4. `StatisticsPage.vue`

### 子任务

1. 在 `375 / 768 / 1024 / 1440` 下截图
2. 标注结构、视觉、响应式、a11y、性能相关问题
3. 按 `阻塞 / 高 / 中 / 低` 做优先级归类
4. 汇总成一份审计记录

### 验收标准

1. 四个关键页面都完成多断点截图
2. 问题列表能映射到后续 backlog 项
3. 至少能明确 P0 问题与非 P0 问题边界

### 依赖

无

### 备注

这是后续所有页面改造的共同参照物。

## FP-P0-02 输出首页/创作页/Skill 执行页 IA 重排方案

### 背景

本轮优化的最大问题被定义为“信息层级和页面结构”，所以 IA 先于视觉微调。

### 目标

为首页、创作页、Skill 执行页明确主任务、主 CTA、证据区、辅助区和状态区。

### 范围

1. 首页
2. 创作页
3. Skill 执行页

### 子任务

1. 输出每个页面的主任务定义
2. 明确主 CTA 和次 CTA
3. 标注哪些区块必须前置，哪些可折叠
4. 形成结构草图或说明文档

### 验收标准

1. 每个页面都能用一句话说清主任务
2. 每个页面只存在一个主 CTA
3. 移动端不再依赖“直接隐藏关键内容”

### 依赖

FP-P0-01

### 备注

这条 issue 完成后，页面开发任务才真正能稳定开跑。

## FP-P0-03 建立 design token v1

### 背景

当前有一套绿色主题变量，但尚未形成真正支持全站统一演进的 token 体系。

### 目标

建立轻量但可扩展的 design token v1。

### 范围

1. 颜色
2. 间距
3. 圆角
4. 阴影
5. 动效时长
6. 字体角色

### 子任务

1. 盘点现有变量
2. 合并重复或语义不清的变量
3. 建立语义化 token 命名
4. 为核心页面准备迁移映射表

### 验收标准

1. token 至少能覆盖首页、创作页、Skill 页、统计页
2. 颜色区分出背景、表面、文本、强调、状态角色
3. 不再只有“深浅绿色变化”的主题感

### 依赖

FP-P0-01

---

## FP-P0-04 统一核心组件状态规范

### 背景

当前不同页面组件状态完整度不一致，Skill 页面相对更完整，其他页面参差不齐。

### 目标

统一核心组件的状态样式和交互规则。

### 范围

1. Button
2. Input / Textarea
3. StatusBadge / Tag
4. Card / Panel
5. Progress
6. Empty / Error / Loading

### 子任务

1. 定义状态矩阵
2. 补齐缺失状态
3. 对齐交互反馈节奏
4. 输出示例与页面映射

### 验收标准

1. 每个核心组件都有完整状态覆盖
2. 焦点态、禁用态、加载态表现统一
3. 组件状态可被首页、创作页、Skill 页直接复用

### 依赖

FP-P0-03

---

## FP-P0-05 重构创作页桌面端结构

### 背景

创作页是正式方案中的第一优先级页面，也是任务完成率的主战场。

### 目标

把创作页桌面布局从“固定三栏”重构为“主工作区 + 可折叠辅助区”。

### 范围

`frontend/src/pages/article/ArticleCreatePage.vue`

### 子任务

1. 重排主工作区、流程、日志、提示的关系
2. 降低侧栏对主内容的抢占
3. 统一阶段切换的大状态结构
4. 保持信息完整但降低噪音

### 验收标准

1. 桌面端主工作区成为绝对视觉中心
2. 侧栏不再压制主流程
3. 阶段变化清晰，不需要用户自己猜

### 依赖

FP-P0-02, FP-P0-03, FP-P0-04

---

## FP-P0-06 重构创作页移动端结构

### 背景

当前移动端通过直接隐藏双侧栏解决布局问题，导致流程连续性明显下降。

### 目标

让创作页在移动端保留完整流程能力，而不是删减版。

### 范围

`frontend/src/pages/article/ArticleCreatePage.vue`

### 子任务

1. 为流程信息设计抽屉或折叠面板
2. 为日志设计移动端容器
3. 为提示信息设计贴近主流程的承载方式
4. 保证重要上下文不消失

### 验收标准

1. `375` 下主流程完整
2. 用户可以找到当前步骤、提示、日志与恢复信息
3. 不再简单依赖 `display: none` 隐藏关键辅助内容

### 依赖

FP-P0-05

## FP-P0-07 优化创作页输入区分组与表单结构

### 背景

你已经确认表单不走极短多步，而走“中等复杂度、一屏完成”。

### 目标

在保留信息完整度的前提下，提升输入区的理解效率。

### 范围

创作页输入态

### 子任务

1. 将选题、风格、配图方式、配额提示做明确分组
2. 调整帮助说明位置
3. 优化默认值与禁用逻辑的解释
4. 控制一屏内的视觉密度

### 验收标准

1. 一屏内完成输入，但不显拥挤
2. 字段关系清楚，用户知道为什么选这个
3. 配额与 VIP 逻辑表达清楚，不打断主任务

### 依赖

FP-P0-02, FP-P0-04, FP-P0-05

---

## FP-P0-08 治理创作页状态反馈与日志表达

### 背景

当前创作页仍有 emoji 和偏情绪化的日志与提示表达，不符合专业工具语气。

### 目标

将状态反馈统一成专业、直接、低情绪的表达方式。

### 范围

创作页日志、提示、进度、阶段文案

### 子任务

1. 替换 emoji 与情绪化提示
2. 明确等待、失败、恢复、完成文案
3. 优化日志密度与层级
4. 保持状态说明贴近当前任务

### 验收标准

1. 页面不再依赖 emoji 表达状态
2. 用户可理解当前状态和下一步
3. 失败和等待不再是黑盒

### 依赖

FP-P0-05, FP-P0-06

---

## FP-P0-09 重构首页首屏结构

### 背景

首页已不再只是获客页，而是回访用户的任务分发台。

### 目标

让首页首屏同时兼顾回访效率和新用户理解。

### 范围

`frontend/src/pages/HomePage.vue`

### 子任务

1. 重写首屏结构
2. 保留产品解释，但降低模板化 Hero 感
3. 突出主 CTA 与次 CTA
4. 加入真实界面暗示或结果预览

### 验收标准

1. 已登录用户进入后 3 秒内能找到下一步
2. 首访用户 5 秒内能理解产品是什么
3. 首屏只有 1 主 1 次 CTA

### 依赖

FP-P0-02, FP-P0-03, FP-P0-04

## FP-P0-10 前置首页回访用户入口

### 背景

你明确了核心用户偏回访用户，因此首页不能继续把高频回访入口放得太后。

### 目标

前置最近创作、继续任务、快捷 Skill 入口。

### 范围

首页已登录态

### 子任务

1. 调整最近创作区域位置
2. 强化继续创作与查看最近任务入口
3. 优化快捷 Skill 的呈现位置和权重

### 验收标准

1. 回访路径明显前置
2. 已登录用户不需要滚动太久才能继续任务
3. 不会因此打乱首屏主任务解释

### 依赖

FP-P0-09

## FP-P0-11 重构首页证据区与任务型内容模块

当前首页仍有偏模板化的能力卡片，需要更贴近真实任务与结果。

### 目标

用真实证据和任务型模块替代部分泛卖点卡。

### 范围

首页中段内容区域

### 子任务

1. 降低普通功能卡片占比
2. 增加真实流程或结果样例
3. 重写模块顺序与标题
4. 让页面更像真实产品而不是功能海报

### 验收标准

1. 前两屏能建立可信度
2. 页面内容更贴近真实使用场景
3. 功能模块不再明显模板化

### 依赖

FP-P0-09

## FP-P0-12 重构 Skill 执行页结构

### 背景

Skill 执行页需要承接“输入 -> 执行 -> 结果”的完整任务路径。

### 目标

让输入区、进度区、结果区结构清晰，降低等待焦虑。

### 范围

`SkillExecutePage.vue` 及相关组件

### 子任务

1. 重排输入区与结果区关系
2. 统一进度区结构
3. 优化一屏输入完成的布局
4. 强化结果承接与回看路径

### 验收标准

1. 用户在执行前就知道要输入什么
2. 执行中状态更清楚
3. 结果展示结构更稳定

### 依赖

FP-P0-02, FP-P0-03, FP-P0-04

## FP-P0-13 为流式内容与异步结果建立稳定容器

### 背景

流式内容和异步结果区域容易造成布局跳动，直接影响体验稳定性和 CLS。

### 目标

为大纲、正文、结果、配图进度等异步区域预留稳定容器。

### 范围

创作页、Skill 执行页

### 子任务

1. 分析跳动来源
2. 预设容器尺寸或最小高度
3. 优化骨架与加载占位
4. 降低流式更新带来的重排

### 验收标准

1. 执行过程中页面无明显跳动
2. 流式内容体验更稳
3. 加载区不会压缩或挤飞其他内容

### 依赖

FP-P0-05, FP-P0-12

---

## FP-P0-14 补齐全站 focus-visible 与键盘主路径

### 背景

局部页面已有 `focus-visible`，但尚未形成全站一致规则。

### 目标

补齐全站高频路径的焦点可见性和键盘可用性。

### 范围

首页、创作页、Skill 页、统计页核心交互

### 子任务

1. 盘点缺失的焦点样式
2. 统一主路径键盘顺序
3. 检查可点击元素的语义与标签
4. 补齐需要的 `aria-live` 与辅助说明

### 验收标准

1. 主流程可以只用键盘完成
2. 焦点可见且不被遮挡
3. 高优先级交互有明确可达路径

### 依赖

FP-P0-04

## FP-P0-15 统一微动效预算并补齐 reduced-motion

### 背景

全局已有 reduced-motion 基础兜底，但页面级动效和节奏还没统一。

### 目标

建立微动效预算，并让关键页面在 reduced-motion 下保持完整可用。

### 范围

首页、创作页、Skill 执行页、全局样式

### 子任务

1. 盘点当前动效
2. 删除非必要动效
3. 统一状态切换时长
4. 为关键交互验证 reduced-motion

### 验收标准

1. 页面动效只服务反馈与连续性
2. reduced-motion 下不影响使用
3. 页面不出现大范围炫技式转场

### 依赖

FP-P0-03, FP-P0-04

---

## FP-P0-16 优化首屏加载与布局稳定性

### 背景

你明确把性能第一优先放在首屏加载与布局稳定性。

### 目标

优先优化首页、创作页、Skill 执行页的首屏性能和布局稳定性。

### 范围

首页、创作页、Skill 执行页

### 子任务

1. 检查图片加载与尺寸声明
2. 检查字体加载成本
3. 减少非必要首屏内容
4. 为异步与流式内容保留稳定空间
5. 优化图表或重组件初始化时机

### 验收标准

1. 首屏主要区域加载稳定
2. 异步内容不会造成大范围跳动
3. 关键页面性能较当前有明确改善

### 依赖

FP-P0-09, FP-P0-12, FP-P0-13
