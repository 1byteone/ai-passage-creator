## 1. 方案定位

这是一版按推荐默认项收敛的实施方案。默认认为：

1. 本轮是对现有产品页面体系做系统优化，不是从零重做
2. 优先目标是提升任务完成率、理解速度、一致性和长期可维护性
3. 设计方向采用 `Precision System`
4. 优先级顺序为：首页 -> 创作页 -> Skill 页面 -> 结果页 -> 后台页
5. 响应式策略采用移动优先，桌面增强
6. 可访问性最低目标为 `WCAG AA`

如果后续你给出问卷答案，这份方案只需要替换少数决策块，不需要推倒重写。

## 2. 默认决策快照

本方案默认采用问卷中的推荐答案 `A` 作为决策基线。

### 2.1 产品与目标

1. 优化对象：已有产品页面体系
2. 覆盖范围：首页、工作流页、结果页、后台页
3. 最高优先目标：任务完成率和转化
4. 核心用户：首次进入的新用户，同时兼顾回访用户效率
5. 页面角色：获客 + 激活 + 工作流混合型

### 2.2 设计与品牌

1. 保留现有绿色品牌方向，但重构色彩角色
2. 整体调性：专业可信
3. 视觉密度：中密度
4. 结构策略：减少无意义卡片化
5. 首屏策略：产品名 + 价值说明 + CTA + 真实界面暗示

### 2.3 交互与体验

1. 创作页使用“主工作区 + 可折叠辅助区”
2. 工作流提示语气偏专业、直接、低情绪
3. 表单优先短表单或分段表单
4. 错误提示使用字段旁提示 + 顶部汇总
5. 动效预算为克制型微动效

### 2.4 工程与质量

1. 建立最小 design token
2. 渐进式重构，而不是一次性重写
3. 建立页面模板和轻量规范
4. 验收覆盖性能、响应式、a11y、状态矩阵

## 3. 本轮优化的成功定义

本轮成功不以“页面更好看”作为唯一标准，而以以下结果成立为准：

1. 新用户进入首页后，能在 5 秒内理解产品、价值和下一步动作
2. 创作流程在移动端不再依赖隐藏侧栏来“解决”布局问题
3. Skill 中心与执行页从功能集合升级为结构清晰的任务工具体验
4. 后台页数据关系更清楚，图表可读性和空态/错态更完整
5. 全站建立一致的 token、状态、交互和响应式底线

## 5. 页面级定制方案

## 5.1 首页

### 当前问题

1. Hero 已可用，但仍偏模板化
2. “核心能力”更像泛能力陈列，而不是任务导向说明
3. 真实证据区偏弱
4. 新用户与回访用户共用同一入口节奏，分流效率一般

### 目标

1. 提升首屏理解速度
2. 提升 CTA 聚焦度
3. 增加真实感与可信度
4. 兼顾新用户启动与回访用户回流

### 结构建议

1. 第一屏：产品名、价值说明、主 CTA、次 CTA、真实界面暗示
2. 第二屏：真实创作流程或结果预览
3. 第三屏：任务型能力分组，而不是普通三列卖点卡
4. 第四屏：最近创作或高频入口，服务回访用户

### 实施项

1. 调整首页 Hero 文案结构
2. 把功能卡片改为任务结果导向模块
3. 引入真实界面截图或流程片段
4. 优化已登录用户的回访路径
5. 降低单一绿色氛围造成的层级疲劳

### 验收

1. 首屏主 CTA 明确且唯一
2. 页面前两屏能解释产品真实能力
3. 回访用户不必滚很久才能回到高频操作

## 5.2 创作页

### 当前问题

1. 三栏布局信息丰富，但主流程专注度一般
2. `992px` 以下直接隐藏侧栏，移动端体验割裂
3. 提示与日志语气不完全统一
4. 部分内容过于“面板化”，注意力被切碎

### 目标

1. 让工作流更连续
2. 让移动端保留完整能力
3. 让状态反馈更专业
4. 提升主工作区的专注感

### 结构建议

1. 桌面：主工作区 + 左右可收展辅助区
2. 平板：主工作区 + 单个可切换辅助抽屉
3. 手机：主工作区全宽，流程/日志/提示进入底部抽屉或顶部折叠区

### 实施项

1. 重新梳理左侧流程、右侧日志、右侧提示的优先级
2. 移除 emoji 和情绪化日志表达
3. 把“创建前 / 创建中 / 确认中 / 已完成”做成更清晰的大状态
4. 让辅助能力进入可折叠容器，而不是直接消失
5. 为长文本、流式内容和图片进度预留稳定空间

### 验收

1. 手机端不丢失关键流程信息
2. 用户始终知道当前步骤和下一步
3. 错误、等待和恢复路径清晰

## 5.3 Skill 中心与执行页

### 当前目标

把 Skill 页面从“功能展示”升级为“任务完成工具”。

### 实施项

1. Skill 卡片突出输入预期与输出结果
2. 执行页统一输入区、进度区、结果区层级
3. 补齐空态、错误态、结果回退态
4. 优化结果组件的阅读与复制路径
5. 强化恢复能力说明与终态反馈

### 验收

1. 用户在点击前就知道要提供什么、会得到什么
2. 执行中的等待焦虑降低
3. 结果可以读、可以复制、可以回看

## 5.4 结果页与文章详情页

### 目标

让结果消费和二次操作更顺手。

### 实施项

1. 统一标题、摘要、正文、图像、导出按钮的层级
2. 增强复制、导出、继续处理、二次调用 Skill 的路径
3. 优化长内容排版、锚点、图像尺寸和阅读节奏
4. 让详情页和完成页之间的体验连续

## 5.5 统计页与后台页

### 目标

让数据更容易被理解，而不是只把卡片和图堆上去。

### 实施项

1. 重排指标卡和图表顺序
2. 为每个图表补充文字摘要或辅助说明
3. 统一颜色角色、单位、时间范围和状态说明
4. 减少无意义悬浮效果，提升内容优先级
5. 加入无数据、异常和加载中的结构化反馈

## 6. 设计系统实施方案

### 6.1 Token 设计

优先建立以下 token：

1. 颜色 token：背景、表面、文本、强调、状态
2. 字体 token：标题、正文、辅助、数字
3. 间距 token：4/8/12/16/24/32/40/48
4. 圆角 token：6/8/12
5. 阴影 token：轻、标准、强调
6. 动效 token：150ms / 200ms / 300ms

### 6.2 基础组件治理顺序

1. Button
2. Input / Textarea
3. StatusBadge / Tag
4. Card / Panel
5. Empty / Error / Loading
6. Progress / Timeline
7. Chart container

### 6.3 页面模板

本轮至少固化 4 套模板：

1. 首页首屏模板
2. 工具目录模板
3. 多阶段工作流模板
4. 数据后台模板

---

## 7. 可访问性与响应式要求

### 7.1 可访问性底线

1. 全站统一 `focus-visible`
2. 主流程支持键盘操作
3. 表单错误支持字段级提示与恢复
4. 流式状态与进度信息使用 `aria-live`
5. 所有交互元素满足触控目标
6. 动画遵守 `prefers-reduced-motion`

### 7.2 响应式断点

必须验收：

1. `375`
2. `768`
3. `1024`
4. `1440`

### 7.3 移动端原则

1. 不直接删功能
2. 辅助信息进入抽屉、折叠区或分段区
3. 主 CTA 和主反馈始终可见
4. 长文本、图表、日志都要有移动策略

---

## 8. 性能实施方案

### 8.1 优先目标

1. 首屏加载
2. 布局稳定
3. 交互流畅
4. 图表与图片成本控制

### 8.2 优先实施项

1. 检查图片尺寸声明与懒加载
2. 评估字体加载成本
3. 控制首屏不必要脚本和渲染内容
4. 图表按可见性或页面时机初始化
5. 为流式内容和异步结果保留稳定容器

## 10. 验收矩阵

### 10.1 视觉与结构

1. 首屏主动作明确
2. 模块任务分工清晰
3. 颜色与层级一致
4. 卡片使用克制

### 10.2 交互与状态

1. hover
2. focus-visible
3. pressed
4. disabled
5. loading
6. empty
7. error
8. success

### 10.3 响应式

1. `375` 无横向滚动
2. `768` 无重叠
3. `1024` 布局重排合理
4. `1440` 留白与密度平衡

### 10.4 可访问性

1. 键盘可用
2. 焦点可见
3. 错误可恢复
4. 对比度达标
5. reduced-motion 生效

### 10.5 性能

1. 首屏渲染稳定
2. 异步内容不明显跳动
3. 图表与图片不拖慢页面

## 11. 风险说明

### 11.1 最大风险

1. 只优化首页，导致工作流页继续拖后腿
2. 只改视觉，不动结构
3. 移动端仍然靠隐藏解决布局
4. 没有 token，后面越改越散

### 11.2 推荐回避方式

1. 先冻结页面优先级
2. 先做系统，再做细节
3. 每个阶段都带验收项
4. 所有新增页面必须挂到模板和 token 上
