## FP-P0-01 建立前端页面审计与截图基线

**背景**

当前已经有正式方案，但缺少一份统一的页面问题基线。后续如果没有截图和问题标注，很容易出现“感觉优化了，但没有统一判断依据”的情况。

**目标**

建立首页、创作页、Skill 执行页、统计页的截图基线、问题标注和优先级矩阵。

**范围**

- `frontend/src/pages/HomePage.vue`
- `frontend/src/pages/article/ArticleCreatePage.vue`
- `frontend/src/pages/skill/SkillExecutePage.vue`
- `frontend/src/pages/admin/StatisticsPage.vue`

**子任务**

- 在 `375 / 768 / 1024 / 1440` 下完成截图
- 标注结构、视觉、响应式、可访问性、性能相关问题
- 按 `阻塞 / 高 / 中 / 低` 做优先级分类
- 汇总成统一审计记录

**验收标准**

- 四个关键页面都完成多断点截图
- 问题列表可映射到后续 backlog
- 能清楚区分 P0 与非 P0 问题

**依赖**

- 无

**备注**

- 这条 issue 是后续页面重构的共同参照物

## FP-P0-02 输出首页/创作页/Skill 执行页 IA 重排方案

**背景**

本轮优化的核心问题已经被定义为“信息层级和页面结构”，因此 IA 重排必须先于视觉微调。

**目标**

为首页、创作页、Skill 执行页明确主任务、主 CTA、证据区、辅助区和状态区。

**范围**

- 首页
- 创作页
- Skill 执行页

**子任务**

- 输出每个页面的主任务定义
- 明确主 CTA 与次 CTA
- 标注哪些区块必须前置，哪些可以折叠
- 形成结构说明或草图

**验收标准**

- 每个页面都能用一句话说清主任务
- 每个页面只保留一个主 CTA
- 移动端不再依赖“直接隐藏关键内容”

**依赖**

- `FP-P0-01`

**备注**

- 这条 issue 完成后，页面开发任务才能稳定推进

## FP-P0-03 建立 design token v1

**背景**

当前已有绿色主题变量，但尚未形成真正支持全站演进的语义化 token 体系。

**目标**

建立轻量但可扩展的 design token v1。

**范围**

- 颜色
- 间距
- 圆角
- 阴影
- 动效时长
- 字体角色

**子任务**

- 盘点现有 CSS 变量
- 合并重复或语义不清的变量
- 建立语义化命名
- 形成页面迁移映射表

**验收标准**

- token 至少能覆盖首页、创作页、Skill 页、统计页
- 颜色包含背景、表面、文本、强调、状态角色
- 页面不再只表现为不同深浅的绿色主题

**依赖**

- `FP-P0-01`

**备注**

- 这是后续组件统一和页面重构的基础层

## FP-P0-04 统一核心组件状态规范

**背景**

当前不同页面的组件状态完整度不一致，Skill 页面相对完整，其他页面仍有明显缺口。

**目标**

统一核心组件的状态样式和交互规则。

**范围**

- Button
- Input / Textarea
- StatusBadge / Tag
- Card / Panel
- Progress
- Empty / Error / Loading

**子任务**

- 定义状态矩阵
- 补齐缺失状态
- 对齐状态反馈节奏
- 输出组件到页面的映射关系

**验收标准**

- 每个核心组件都有完整状态覆盖
- 焦点态、禁用态、加载态表现统一
- 可被首页、创作页、Skill 页直接复用

**依赖**

- `FP-P0-03`

**备注**

- 推荐与 token 任务并行推进

## FP-P0-05 重构创作页桌面端结构

**背景**

创作页是当前产品任务完成率的主战场，也是正式方案中的第一优先级页面。

**目标**

把创作页桌面布局从“固定三栏”重构为“主工作区 + 可折叠辅助区”。

**范围**

- `frontend/src/pages/article/ArticleCreatePage.vue`

**子任务**

- 重排主工作区、流程、日志、提示的层级关系
- 降低侧栏对主流程的干扰
- 统一阶段切换的大状态结构
- 保持信息完整但降低噪音

**验收标准**

- 桌面端主工作区成为绝对视觉中心
- 侧栏不再压制主流程
- 阶段变化清晰，不需要用户自己猜

**依赖**

- `FP-P0-02`
- `FP-P0-03`
- `FP-P0-04`

**备注**

- 建议与移动端结构任务拆开推进

## FP-P0-06 重构创作页移动端结构

**背景**

当前移动端通过隐藏双侧栏解决空间问题，导致流程连续性与上下文信息明显缺失。

**目标**

让创作页在移动端保留完整能力，而不是缩水版。

**范围**

- `frontend/src/pages/article/ArticleCreatePage.vue`

**子任务**

- 为流程信息设计抽屉或折叠面板
- 为日志设计移动端容器
- 为提示信息设计贴近主流程的承载方式
- 保证重要上下文不消失

**验收标准**

- `375` 下主流程完整
- 用户能找到当前步骤、提示、日志和恢复信息
- 不再简单依赖隐藏关键辅助内容

**依赖**

- `FP-P0-05`

**备注**

- 这是 P0 里最直接影响移动端体验的一条

## FP-P0-07 优化创作页输入区分组与表单结构

**背景**

当前方案已确认表单采用“中等复杂度、一屏完成”，因此重点不是继续压缩字段，而是提升组织质量。

**目标**

在保留信息完整度的前提下，提升输入区理解效率和填写体验。

**范围**

- 创作页输入态

**子任务**

- 将选题、风格、配图方式、配额提示做明确分组
- 调整帮助说明位置
- 优化默认值与禁用逻辑说明
- 控制一屏内的视觉密度

**验收标准**

- 一屏内完成输入，但不显拥挤
- 字段关系清楚
- 配额与 VIP 逻辑表达清楚，不打断主任务

**依赖**

- `FP-P0-02`
- `FP-P0-04`
- `FP-P0-05`

**备注**

- 这条和桌面结构重构最好同步设计、分开实现

## FP-P0-08 治理创作页状态反馈与日志表达

**背景**

创作页仍有 emoji 和偏情绪化日志表达，不符合专业工具页的统一语气。

**目标**

将状态反馈统一成专业、直接、低情绪的表达方式。

**范围**

- 创作页日志
- 提示
- 阶段文案
- 进度反馈

**子任务**

- 替换 emoji 与情绪化提示
- 明确等待、失败、恢复、完成文案
- 优化日志密度与层级
- 保持状态说明贴近当前任务

**验收标准**

- 页面不再依赖 emoji 表达状态
- 用户可以理解当前状态和下一步
- 失败和等待不再像黑盒

**依赖**

- `FP-P0-05`
- `FP-P0-06`

**备注**

- 这条适合在结构稳定后快速收口

## FP-P0-09 重构首页首屏结构

**背景**

首页已被重新定义为“回访用户任务分发台 + 首访用户理解入口”，不能继续停留在传统模板 Hero 层级。

**目标**

让首页首屏同时兼顾回访效率和新用户理解。

**范围**

- `frontend/src/pages/HomePage.vue`

**子任务**

- 重写首屏结构
- 保留产品解释，但降低模板化 Hero 感
- 突出主 CTA 与次 CTA
- 加入真实界面暗示或结果预览

**验收标准**

- 已登录用户 3 秒内能找到下一步
- 首访用户 5 秒内能理解产品是什么
- 首屏只有 1 主 1 次 CTA

**依赖**

- `FP-P0-02`
- `FP-P0-03`
- `FP-P0-04`

**备注**

- 推荐与回访入口前置任务分开建单

## FP-P0-10 前置首页回访用户入口

**背景**

正式方案已经确认核心用户偏回访用户，因此首页必须更快承接“继续任务”和“回到高频路径”。

**目标**

前置最近创作、继续任务、快捷 Skill 入口。

**范围**

- 首页已登录态

**子任务**

- 调整最近创作区域位置
- 强化继续创作与查看最近任务入口
- 优化快捷 Skill 的位置和权重

**验收标准**

- 回访路径明显前置
- 已登录用户不需要滚很久才能继续任务
- 不会打乱首屏主任务解释

**依赖**

- `FP-P0-09`

**备注**

- 这是首页“回访优先”策略的关键落点

当前首页仍保留较强的模板化功能卡片感，真实证据区不足。

**目标**

**范围**

**子任务**

- 增加真实流程或结果样例

- 让内容更贴近真实使用场景

**验收标准**

- 前两屏能建立可信度
- 页面内容更像真实产品，而不是功能海报
- 中段内容不再明显模板化

**依赖**

**备注**

- 这条适合和首页首屏改造并行设计

## FP-P0-13 为流式内容与异步结果建立稳定容器

**背景**

流式内容和异步结果区域容易引发布局跳动，直接影响体验稳定性和 CLS。

**目标**

为大纲、正文、结果、配图进度等异步区域预留稳定容器。

**范围**

- 创作页
- Skill 执行页

**子任务**

- 分析跳动来源
- 预设容器尺寸或最小高度
- 优化骨架与加载占位
- 降低流式更新带来的重排

**验收标准**

- 执行过程中页面无明显跳动
- 流式内容体验更稳
- 加载区不会压缩或挤飞其他内容

**依赖**

- `FP-P0-05`
- `FP-P0-12`

**备注**

- 这是体验稳定和性能稳定的共同支点

## FP-P0-14 补齐全站 focus-visible 与键盘主路径

**背景**

局部页面已有 `focus-visible`，但尚未形成全站一致规则。

**目标**

补齐全站高频路径的焦点可见性和键盘可用性。

**范围**

- 首页
- 创作页
- Skill 页
- 统计页核心交互

**子任务**

- 盘点缺失焦点样式
- 统一主路径键盘顺序
- 检查交互元素的语义和标签
- 补齐必要的 `aria-live` 与辅助说明

**验收标准**

- 主流程可以只用键盘完成
- 焦点可见且不被遮挡
- 高优先级交互有清晰可达路径

**依赖**

- `FP-P0-04`

**备注**

- 推荐在页面改造同时持续推进

## FP-P0-15 统一微动效预算并补齐 reduced-motion

**背景**

全局已有 reduced-motion 基础兜底，但页面级动效和节奏还没统一。

**目标**

建立微动效预算，并让关键页面在 reduced-motion 下保持完整可用。

**范围**

- 首页
- 创作页
- Skill 执行页
- 全局样式

**子任务**

- 盘点当前动效
- 删除非必要动效
- 统一状态切换时长
- 为关键交互验证 reduced-motion

**验收标准**

- 动效只服务反馈和连续性
- reduced-motion 下不影响使用
- 页面不出现炫技式大范围转场

**依赖**

- `FP-P0-03`
- `FP-P0-04`

**备注**

- 推荐在组件状态统一后同步收口

## FP-P0-16 优化首屏加载与布局稳定性
