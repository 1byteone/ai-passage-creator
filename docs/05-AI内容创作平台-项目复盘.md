# AI 内容创作平台 - 项目复盘文档

> **项目名称**: AI Passage Creator - 企业级 AI 内容创作平台
> **技术栈**: Spring Boot 3.5 + Spring AI Alibaba + 多 Agent 编排 + Stripe 支付
> **复盘日期**: 2026-06-01

## 一、用户故事（User Stories）

### 1.1 内容创作者用户故事

#### 故事 1：快速生成爆款文章标题
```
作为一名 内容创作者
我希望 输入一个选题后，系统能自动生成 3-5 个爆款标题方案
以便于 我能快速选择最吸引人的标题，节省构思时间

验收标准：
- 系统在 5 秒内生成标题方案
- 每个方案包含主标题和副标题
- 标题符合新媒体爆款风格
- 支持不同文章风格（科技、情感、教育、幽默）
```

#### 故事 2：可视化大纲编辑
```
作为一名 内容创作者
我希望 在确认标题后，系统能自动生成结构化大纲并支持 AI 修改
以便于 我能快速调整文章结构，无需手动重写

验收标准：
- 系统生成包含 3-5 个章节的大纲
- 每个章节有明确的标题和要点
- 支持 AI 根据用户建议自动修改大纲
- 用户可以手动编辑大纲内容
```

#### 故事 3：实时查看文章生成进度
```
作为一名 内容创作者
我希望 在文章生成过程中，实时看到每个阶段的进度
以便于 我了解任务执行状态，合理安排时间

验收标准：
- 通过 SSE 实时推送进度
- 显示当前执行阶段（标题生成/大纲生成/正文生成/配图生成）
- 支持流式显示大纲和正文内容
- 显示错误信息便于排查
```

#### 故事 4：自动配图生成
```
作为一名 内容创作者
我希望 系统能根据文章内容自动生成配图
以便于 我的文章更加生动，无需手动寻找图片

验收标准：
- 支持多种配图方式（Pexels 图库、AI 生图、Mermaid 图表、Iconify 图标等）
- 封面图自动生成
- 配图位置合理，与内容相关
- 支持并行生成多张配图
```

### 1.2 VIP 用户故事

#### 故事 5：购买永久会员
```
作为一名 普通用户
我希望 通过 Stripe 支付购买永久 VIP 会员
以便于 我能享受无限创作配额和高级功能

验收标准：
- 支持 Stripe 支付
- 支付成功后立即升级为 VIP
- VIP 用户拥有无限创作配额
- 支持退款流程
```

### 1.3 系统管理员故事

#### 故事 6：统计分析
```
作为一名 系统管理员
我希望 查看系统运营统计数据
以便于 了解平台使用情况和用户活跃度

验收标准：
- 显示今日/本周/本月创作数量
- 显示任务成功率
- 显示平均生成耗时
- 显示活跃用户数和 VIP 用户数
- 支持缓存优化
```

#### 故事 7：Agent 执行日志
```
作为一名 系统管理员
我希望 查看 AI Agent 的执行日志和性能数据
以便于 监控系统健康度和优化性能

验收标准：
- 自动记录每个 Agent 的执行时间
- 记录输入输出数据
- 记录执行状态和错误信息
- 支持按任务查询日志
```

## 二、功能需求描述

### 2.1 核心功能模块

#### 模块 1：多 Agent 文章生成系统

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 标题生成 Agent | 根据选题生成 3-5 个爆款标题方案 | P0 |
| 大纲生成 Agent | 根据标题生成结构化大纲，支持流式输出 | P0 |
| 正文生成 Agent | 根据大纲生成文章正文，支持流式输出 | P0 |
| 配图分析 Agent | 分析正文内容，识别配图需求 | P0 |
| 图片生成 Agent | 支持多种方式生成配图 | P0 |
| 图文合成 Agent | 将配图插入正文，生成完整图文 | P0 |

#### 模块 2：人机协作流程

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 三阶段流程 | 标题选择 → 大纲编辑 → 正文生成 | P0 |
| 状态机管理 | 管理任务状态（PENDING/PROCESSING/COMPLETED/FAILED） | P0 |
| SSE 进度推送 | 实时推送生成进度 | P0 |
| AI 修改大纲 | 根据用户建议 AI 自动修改大纲 | P1 |

#### 模块 3：多智能体编排

| 功能 | 描述 | 优先级 |
|------|------|--------|
| StateGraph 编排 | 使用 Spring AI Alibaba 的 StateGraph 编排 Agent | P0 |
| 并行配图生成 | 不同类型配图并行生成，提升效率 | P1 |
| 状态共享 | Agent 间共享 ArticleState 状态对象 | P0 |

#### 模块 4：会员与支付系统

| 功能 | 描述 | 优先级 |
|------|------|--------|
| VIP 购买 | 支持 Stripe 支付购买永久会员 | P0 |
| Webhook 回调 | 处理 Stripe 支付成功/失败回调 | P0 |
| 配额管理 | 普通用户配额限制，VIP 用户无限配额 | P0 |
| 退款处理 | 支持 Stripe 退款，撤销 VIP 身份 | P1 |

#### 模块 5：日志与统计

| 功能 | 描述 | 优先级 |
|------|------|--------|
| Agent 执行日志 | AOP 自动记录 Agent 执行信息 | P1 |
| 运营统计 | 创作数量、成功率、平均耗时等统计 | P1 |
| Redis 缓存 | 统计数据缓存优化 | P1 |

### 2.2 配图方式支持

### 3.2 多智能体编排流程（StateGraph）

```java
// 阶段 3 编排图：正文生成 -> 配图分析 -> 并行配图生成 -> 图文合成
private StateGraph buildPhase3Graph() {
    return new StateGraph(keyStrategyFactory)
        // 节点定义
        .addNode("content_generator", node_async(contentGeneratorAgent))
        .addNode("image_analyzer", node_async(imageAnalyzerAgent))
        .addNode("parallel_image_generator", node_async(parallelImageGenerator))
        .addNode("content_merger", node_async(contentMergerAgent))
        // 边定义：顺序执行
        .addEdge(START, "content_generator")
        .addEdge("content_generator", "image_analyzer")
        .addEdge("image_analyzer", "parallel_image_generator")
        .addEdge("parallel_image_generator", "content_merger")
        .addEdge("content_merger", END);
}
```

## 五、原理剖析

### 5.1 Spring AI Alibaba 多智能体编排原理

#### 5.1.1 StateGraph 核心概念

Spring AI Alibaba 提供了类似 LangGraph 的状态图编排能力：

```java
// 1. 创建状态图
StateGraph graph = new StateGraph(keyStrategyFactory);

// 2. 添加节点（每个节点是一个 NodeAction）
graph.addNode("content_generator", node_async(contentGeneratorAgent));

// 3. 定义边（控制执行流程）
graph.addEdge(START, "content_generator");
graph.addEdge("content_generator", "image_analyzer");

// 4. 编译并执行
CompiledGraph compiledGraph = graph.compile();
Optional<OverAllState> result = compiledGraph.invoke(inputs);
```

#### 5.1.2 状态共享机制

- **KeyStrategyFactory**: 定义状态键的存储策略（ReplaceStrategy 表示覆盖更新）
- **OverAllState**: 所有 Agent 共享的状态容器
- **NodeAction 接口**: 所有 Agent 实现此接口，通过 `apply(OverAllState state)` 方法访问和修改状态

```java
@Component
```

### 5.3 并行配图生成原理

#### 5.3.1 分组并行策略

```java
public class ParallelImageGenerator implements NodeAction {

    @Override
    public Map<String, Object> apply(OverAllState state) throws Exception {
        List<ImageRequirement> requirements = ...;

        // 按 imageSource 分组
        Map<String, List<ImageRequirement>> groupedBySource = requirements.stream()
            .collect(Collectors.groupingBy(ImageRequirement::getImageSource));

        // 并行执行
        List<ArticleState.ImageResult> allImages = executeParallel(groupedBySource, streamHandler);

        return Map.of("images", allImages);
    }

    private List<ImageResult> executeParallel(
            Map<String, List<ImageRequirement>> groupedBySource,
            Consumer<String> streamHandler) {

        CopyOnWriteArrayList<ImageResult> allImages = new CopyOnWriteArrayList<>();

        // 为每种 imageSource 创建异步任务
        List<CompletableFuture<Void>> futures = groupedBySource.entrySet().stream()
            .map(entry -> CompletableFuture.runAsync(() -> {
                String imageSource = entry.getKey();
                List<ImageRequirement> requirements = entry.getValue();

                // 同一类型内部串行执行
                for (ImageRequirement req : requirements) {
                    ImageGenerationResult result = imageGenerationTool.generateImageDirect(...);
                    allImages.add(convertToImageResult(result));

                    // 推送单张配图完成消息
                    if (streamHandler != null) {
                        streamHandler.accept(SseMessageTypeEnum.IMAGE_COMPLETE.getStreamingPrefix()
                            + GsonUtils.toJson(imageResult));
                    }
                }
            }))
            .toList();

        // 等待所有任务完成
        CompletableFuture.allOf(futures.toArray(new CompletableFuture[0])).join();

        return new ArrayList<>(allImages);
    }
}
```

#### 5.3.2 设计权衡

- **不同类型并行**: Pexels 检索、AI 生图、Mermaid 图表可以同时进行
- **同类型串行**: 同一类型内部串行执行，避免 API 限流
- **线程安全**: 使用 `CopyOnWriteArrayList` 收集结果

```java
@Aspect
@Component
public class AgentExecutionAspect {

    @Around("@annotation(agentExecution)")
    public Object aroundAgentExecution(ProceedingJoinPoint pjp, AgentExecution agentExecution) throws Throwable {

        // 提取 taskId 和输入数据
        String taskId = extractTaskId(pjp);

        // 创建日志对象

            .taskId(taskId)
            .agentName(agentExecution.value())
            .startTime(LocalDateTime.now())
            .status("RUNNING")
            .build();

        try {
            // 执行目标方法
            Object result = pjp.proceed();

            // 记录成功
            agentLog.setStatus("SUCCESS");
            agentLog.setDurationMs((int) (System.currentTimeMillis() - startTime));

        } catch (Throwable e) {
            // 记录失败
            agentLog.setStatus("FAILED");
            agentLog.setErrorMessage(e.getMessage());
            throw e;
        } finally {
            // 异步保存日志
            agentLogService.saveLogAsync(agentLog);
        }

        return result;
    }
}
```
