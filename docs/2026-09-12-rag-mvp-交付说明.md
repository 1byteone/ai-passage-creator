# RAG 研发知识库 MVP 交付说明

## 1. 交付范围

本次在 `dev_rag` 分支完成 Phase 0 + Phase 1 的可运行 MVP：

- 当前项目固定为唯一知识库范围。
- Git 为正式事实源，扫描根目录核心规范文件和 `docs/knowledge/**/*.md`。
- Markdown 按一级到六级标题切分为章节，来源绑定仓库路径、章节、分支和 commit。
- 手工上传保留，但默认 `PENDING_REVIEW`，审核通过后才建立向量索引。
- 关键词检索与现有 pgvector 语义检索合并，按 source 去重并返回引用元数据。
- 第一阶段只读：同步只读取工作树；AI 没有改 Git、提交代码或执行生产操作的能力。

## 2. API

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| `POST` | `/api/rag/knowledge/sync` | admin | 同步固定 Git 文档并重建对应章节索引 |
| `POST` | `/api/rag/knowledge/search` | 登录用户 | 只读混合检索，返回 `CONFIRMED/UNCONFIRMED` 状态、来源、路径、commit、章节和领域 |
| `POST` | `/api/rag/document` | admin | 手工登记文档，状态为 `PENDING_REVIEW` |
| `POST` | `/api/rag/document/{id}/approve` | admin | 审核文档并建立正式向量索引 |
| `GET` | `/api/rag/documents` | admin | 查看包括待审核文档在内的登记记录 |
| `DELETE` | `/api/rag/document/{id}` | admin | 删除登记和向量 |

## 3. 使用流程

1. 在 `docs/knowledge/` 补充或修改 Markdown，并提交到当前 Git 分支。
2. 管理员调用同步接口，系统读取固定范围文档并按章节幂等重建索引。
3. 通过 `/rag/knowledge/search` 查询，回答端应展示 `sourcePath`、`sectionPath` 和 `commitSha`。
4. 临时资料可从后台上传；上传后先审核，审核通过后才可被知识库正式检索。

## 4. 关键实现文件

- `RagKnowledgeSyncService`：固定路径扫描、Git 元数据、Markdown 章节切分和 SHA-256。
- `RagKnowledgeBaseService`：关键词/向量结果合并和引用输出。
- `RagDocumentStore`：文档状态、审核、Git upsert、索引删除。
- `RagService`：现有向量库、清洗、分块、熔断和 metadata 索引能力。
- `V13__rag_knowledge_governance.sql`：生产数据库迁移。
- `KnowledgePage.vue`：后台同步、状态展示和审核入口。
- `RagKnowledgeAuthorizationIntegrationTest`：真实 Spring AOP、Session、参数校验和普通用户越权验收。

## 6. MVP 已知边界

- 当前关键词检索使用 `rag_document` 的数据库 LIKE 查询，适合 MVP，不适合大规模代码全文检索；后续可接入专用全文索引。
- 当前 Git 同步通过固定 `git` 只读命令获取分支和 commit，未接入 webhook 或自动 CI 触发。
- 当前权限主要沿用登录/admin 体系，尚未建设团队级细粒度 ACL。
- 当前回答 API 返回检索引用，不包含 LLM 问答编排；这是有意保留的只读安全边界。
- 当前检索 API 在无证据时返回 `UNCONFIRMED` 和“知识库未确认”，不生成未经来源支持的答案。
- 旧文档升级后被标记为 `ACTIVE` 以保持原有行为，新手工文档必须审核。
