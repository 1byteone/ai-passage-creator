# 灵犀写作｜AI 生成与流式响应项目复盘

## 1. 这一项职责在项目中的定位

- AI 项目最容易停留在“调用模型接口能返回文本”这个层面。
- 我负责把大模型能力真正接进业务链路里：让它能生成结构化标题、大纲、正文、配图需求，并且以流式方式实时返回给前端。
- 这一块直接决定用户对产品“智能”和“好用”的第一感知。

一句话面试表达：

> 我基于 `Spring AI Alibaba + DashScope` 封装了标题、大纲、正文和配图需求的生成能力，通过 Prompt 模板、结构化 JSON 解析和 SSE 流式推送，把 AI 能力工程化地接入了业务系统。

---

## 2. 功能描述

### 业务目标

- 给用户输入一个选题，系统不仅要生成文章，还要生成一篇“可用的、可编辑的、带图的文章”。

### 我负责的技术能力

- Prompt 模板设计
- 大模型调用封装
- 结构化结果解析
- 流式生成回传
- 非稳定输出的容错处理

---

## 3. 业务流程

### 标题生成

1. 用户输入选题和风格
2. 标题 Agent 生成 3~5 组标题方案
3. 前端展示候选标题，用户选择

### 大纲生成

1. 用户确认标题并补充个性化描述
2. 大纲 Agent 输出结构化章节列表
3. 系统流式推送生成过程
4. 用户确认或微调大纲

### 正文生成

1. 正文 Agent 根据大纲生成 Markdown 正文
2. 流式推送正文 chunk
3. 前端逐段渲染，提高生成感知

### 配图需求生成

1. 图片分析 Agent 读取正文
2. 输出“哪些位置插图、插什么类型图、对应关键词/提示词”
3. 后续交由配图策略层执行

## 4. 核心设计

### 4.1 Prompt 模板化

为什么不用在代码里直接拼大段字符串：

- 不利于维护
- 不利于后续迭代 Prompt
- 风格能力难复用

当前项目做法：

- 将标题、大纲、正文、配图需求拆成独立 Prompt 常量
- 再根据 `style` 追加风格化 Prompt

### 4.2 结构化输出

大纲和配图需求这种结果，不能只返回自然语言，否则后端没法继续处理。

所以我的处理方式是：

- 用 Prompt 强约束输出 JSON 结构
- 后端用 Gson / DTO 做结构化反序列化
- 对异常 JSON 增加自动修复逻辑

> 面试时建议这样说：  
> “项目采用结构化输出约束的思路，当前代码实现主要是 Prompt + JSON DTO 解析 + 容错修复。”  
> 如果你直接说 `StructuredOutputConverter`，面试官继续深问时要能圆回来：理念一致，但当前项目实际实现更偏手工结构化解析。

### 4.3 流式响应

为什么要流式：

- 正文生成通常较长
- 如果最后一次性返回，用户等待焦虑很强
- 流式输出更接近 ChatGPT 的交互体验

项目做法：

- 使用 `chatModel.stream(...)`
- 每收到一个 chunk 就推送到前端
- 利用 SSE 传输 `AGENT2_STREAMING` / `AGENT3_STREAMING`

## 5. 代码窗口

### 5.1 大纲生成 Agent

```java
@Component
public class OutlineGeneratorAgent implements NodeAction {

    private final DashScopeChatModel chatModel;

    @Override
    public Map<String, Object> apply(OverAllState state) {
        String prompt = PromptConstant.AGENT2_OUTLINE_PROMPT
                .replace("{mainTitle}", mainTitle)
                .replace("{subTitle}", subTitle)
                .replace("{descriptionSection}", descriptionSection)
                + getStylePrompt(style);

        Consumer<String> streamHandler = StreamHandlerContext.get();
        String content = callLlmWithStreaming(prompt, streamHandler);

        ArticleState.OutlineResult outlineResult;
        try {
            outlineResult = GsonUtils.fromJson(content, new TypeToken<ArticleState.OutlineResult>() {});
        } catch (Exception e) {
            String fixedContent = tryFixJson(content);
            outlineResult = GsonUtils.fromJson(fixedContent, new TypeToken<ArticleState.OutlineResult>() {});
        }

        return Map.of("outline", outlineResult);
    }
}
```

### 5.2 正文流式生成

```java
private String callLlmWithStreaming(String prompt, Consumer<String> streamHandler) {
    StringBuilder contentBuilder = new StringBuilder();

    Flux<ChatResponse> streamResponse = chatModel.stream(new Prompt(new UserMessage(prompt)));

    streamResponse
            .doOnNext(response -> {
                String chunk = response.getResult().getOutput().getText();
                if (chunk != null && !chunk.isEmpty()) {
                    contentBuilder.append(chunk);
                    if (streamHandler != null) {
                        streamHandler.accept("AGENT3_STREAMING:" + chunk);
                    }
                }
            })
            .blockLast();

    return contentBuilder.toString();
}
```

### 5.3 JSON 修复逻辑

```java
private String tryFixJson(String json) {
    String fixed = json.trim();

    int openBraces = 0;
    int openBrackets = 0;
    boolean inString = false;
    boolean escaped = false;

    for (int i = 0; i < fixed.length(); i++) {
        char c = fixed.charAt(i);
        if (escaped) {
            escaped = false;
            continue;
        }
        if (c == '\\') {
            escaped = true;
            continue;
        }
        if (c == '"') {
            inString = !inString;
            continue;
        }
        if (!inString) {
            if (c == '{') openBraces++;
            else if (c == '}') openBraces--;
            else if (c == '[') openBrackets++;
            else if (c == ']') openBrackets--;
        }
    }

    StringBuilder sb = new StringBuilder(fixed);
    if (inString) sb.append("\"");
    while (openBrackets-- > 0) sb.append("]");
    while (openBraces-- > 0) sb.append("}");
    return sb.toString();
}
```

### 5.4 SSE 推送流式内容

private Map<String, Object> buildStreamingData(SseMessageTypeEnum type, String content) {

## 7. 面试常问问题与应对回答

### Q1：为什么要结构化输出？直接让模型返回 Markdown 不行吗？

标准回答：

> 标题和正文可以偏自然语言，但大纲和配图需求必须结构化，否则后端没法稳定地继续编排流程。结构化输出是 AI 能否接入业务链路的关键。

### Q2：模型输出 JSON 不规范怎么办？

标准回答：

> 我做了两层处理：第一层是 Prompt 约束，第二层是后端容错解析。对于常见的截断型错误，我会自动补全括号和引号，再重试反序列化，尽量提高成功率。

### Q3：为什么选择 SSE，而不是直接等全文生成完成？

标准回答：

> 因为正文生成耗时长，如果一直没有反馈，用户体验会很差。SSE 让用户能实时看到生成过程，同时服务端实现成本也低于 WebSocket。

### Q4：Prompt 模板怎么设计的？

标准回答：

> 我的思路是“主模板 + 风格补充模板”。主模板负责结构和输出格式约束，风格模板负责技术风、情感风、科普风等写作特征控制。这样复用性更好。

### Q5：如果大模型响应很慢，你会怎么继续优化？

标准回答：

> 我会从三个方向优化：一是缩短 Prompt 和输出长度，二是把更多步骤拆成短链路，三是对图片生成、审核等非关键路径继续异步化，降低首屏等待时间。
