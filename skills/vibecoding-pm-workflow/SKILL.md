# Vibecoding PM Workflow

## 总则

这项 Skill 有两个模式：`prototype` 低保真原型和 `audit` 页面全流程巡查。两种模式都必须遵循“盘点 -> 确认 -> 执行 -> 验证 -> 交付”。

不得把 PRD 中没有明确说明的内容当成既定需求。发现信息缺失时写入 `待确认`，并在执行前暂停等待用户确认。

## 通用准备

1. 读取 PRD、需求附件、现有路由、页面组件、API 契约和测试入口。
2. 提取角色、前置条件、主流程、分支、页面状态、错误恢复和验收标准。
3. 输出一份确认清单，至少包含：
   - 流程分组
   - 页面或页面状态
   - 用户操作
   - 操作后的页面/状态
   - 待确认项
4. 停止执行，等待用户确认范围。没有明确确认，不生成 HTML、不截图、不提交反馈、不修改业务代码。

确认落在工作台页面内完成：流程项逐条勾选后「生成」按钮才可用，AI 侧只负责产出草案，不代替用户做确认。

## 模式 A：低保真原型 `prototype`

### 目标

根据已确认的 PRD 生成一个可直接打开的单文件 HTML 线框图，用于从头到尾检查产品流程，而不是制作正式 UI。

### 执行规则

- 单个 HTML 文件包含全部流程分组和页面屏幕。
- 只使用黑、白、灰、基础边框、文字、按钮轮廓和图片占位块。
- 按用户真实使用顺序从上到下排列；每组有清晰标题。
- 布局用纵向平铺而不是网格：分组按「连续同名」合并成视觉分段，屏与屏之间、组与组之间用连接线贯通，读者从上往下就是一次完整流程。
- 每一屏标注全局序号、组内序号（第 x/y 屏）、页面名称、当前状态、用户可操作项和下一页面/状态。
- 至少检查 PRD 是否涉及首次使用、权限申请、加载中、无数据、失败、重试、取消、恢复和完成状态。
- 未在 PRD 中说明的交互、字段、权限或业务规则标为 `待确认`，不得自行设计。
- 文件不依赖 CDN、外部字体、远程图片或构建工具，双击即可查看。

### 原型交付检查

- 页面清单和跳转关系与用户确认版一致。
- 正常路径和异常路径都能从线框中追踪。
- 所有按钮和状态文案都能对应 PRD。
- HTML 可离线打开，浏览器控制台无阻塞错误。
- 输出文件路径、覆盖范围、待确认项和未覆盖风险。

## 模式 B：页面全流程巡查 `audit`

### 目标

将已实现产品按真实用户旅程组织为可执行的上线前验收走查页，形成反馈闭环和下一轮回归依据。

### 执行规则

- 先列出流程分组、页面、状态、前置数据和复现方式，等待确认后才开始截图或浏览器操作。
- 每个检查项必须包含：页面名称、流程分组、当前状态、复现步骤、预期结果、实际结果、反馈输入框和三个快捷标记：`可以`、`待改`、`阻塞`。
- 覆盖正常流程、重要分支、首次使用、权限、加载、空数据、错误、恢复和重复提交等风险状态。
- 反馈输入后自动保存到 `localStorage` 或项目既有本地存储适配层。
- 支持导出 Markdown 和 JSON；导出内容应包含时间、轮次、页面、状态、复现步骤、反馈、标记和回归状态。
- 新一轮走查加载上一轮结果，保留上一轮反馈原话；对改动页面显示 `已改动`，对未验证项显示 `待回归`。
- 不能把含密码、Token、API Key、Cookie 或个人信息的原始值写入导出文件；必要时脱敏。

### 走查交付检查

- 每个流程组从入口到完成状态可连续执行。
- 每个阻塞项有明确复现步骤和影响范围。
- 反馈保存后刷新页面仍存在。
- Markdown 可直接交给 AI 或开发人员，JSON 可被程序再次导入。
- 回归轮次能区分新增问题、遗留问题、已修复和待验证问题。
- 输出测试环境、账号类型、测试数据版本、浏览器、时间和结论。

## 当前项目适配经验

- 前端页面优先复用 Vue 3、Ant Design Vue、Pinia、Vue Router 和现有请求封装。
- 原型 HTML 由 `frontend/src/services/vibecodingWorkflow.ts` 的 `buildPrototypeHtml` 生成：纯字符串拼接、内联 CSS、无外部依赖，双击即可打开；结构化断言在 `frontend/tests/vibecoding-workflow.test.ts`。
- 手写页面的排版预估通过 `frontend/src/services/textLayout.ts` 隔离 Pretext API，并保留 Canvas/Intl.Segmenter 不可用时的确定性降级。
- 后端 API 的 `BaseResponse` 需要在前端正确解包 `response.data.data`；图片预览必须断言 URL 字符串和实际 `image/png` 响应，不能只检查接口 HTTP 200。
- 关键交付至少执行类型检查、生产构建、纯逻辑测试、页面 UI 测试和真实接口联调。
- 真实环境依赖 MySQL、Redis、Session、Playwright 渲染引擎和 COS；任一依赖不可用都要在交付报告中单独列为风险。

## 推荐输出结构

1. 执行范围和用户确认记录
2. 页面/状态/跳转清单
3. 测试数据和环境
4. 执行结果与证据
5. 缺陷、风险和阻塞项
6. 文件路径、导出物和后续回归计划
